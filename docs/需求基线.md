# 零、调研结论与路线选择

## 0.1 项目应该做成什么

**建议建设一个“标量射频级联分析引擎 + 中文交互界面 + 多格式工程文档导出器”，而不是第一版就建设通用射频仿真平台。**

核心工作流为：

```text
建立项目与分析条件
        ↓
编辑有序器件链路、检查参数及参考点
        ↓
规范化数据 → 逐项校验 → 生成不可变计算输入快照
        ↓
线性增益／噪声／IP3 分析 + 独立的压缩估算
        ↓
统一结果对象与统一图形场景
        ↓
中文界面｜可重算 Excel｜原生 draw.io 图形｜SVG｜可选原生 VSDX
```

这样既符合截图指定的 Python、Streamlit、Excel 和框图方向，又能把计算可信度、文件可编辑程度和工程维护性分别验证，避免“界面看上去完整，公式和导出实际上不可用”。

## 0.2 相关软件与项目调研

下表描述官方文档中确认的能力。“本项目采用方式”是设计建议；“没有发现”不等于产品绝对没有该能力。

| 工具／项目 | 已核实能力与定位 | 与本项目的关系 | 本项目采用方式 |
|---|---|---|---|
| **ADI ADIsimRF** | 官方介绍支持最多 50 个级联单元，分析信号电平、失真、噪声，并提供频率相关器件模型。[S01][S02] | 接近传统射频链路预算工作流；现有器件模型有参考价值 | 参考参数组织和逐级结果；可作为用户有环境时的对照工具，不把其安装或模型数据库作为运行前提 |
| **MathWorks RF Budget Analyzer／RF Toolbox** | 支持二端口链路、放大器、网络和变频器件；`rfbudget` 提供增益、NF、IP3、功率、SNR 等预算结果，并区分 Friis 与谐波平衡求解。[S03][S04] | 提供从预算分析到更复杂仿真的成熟分层思路 | 用于方法与可选数值对照；不要求最终用户购买 MATLAB 才能使用本项目 |
| **Keysight RF System Design／PathWave System Design（SystemVue）** | 官方产品页展示 RF-aware 系统仿真、频率／功率等多维分析及射频与基带系统设计能力。[S06] | 能力范围明显大于单条标量链路预算 | 借鉴“预算与系统仿真分层”的边界，不尝试第一版复刻其求解器 |
| **TI RF Cascade Calculator** | 官方 v1.0.0 说明支持浏览器内最多 10 级、Gain/NF/OIP3/OIP2/OP1dB、逐级结果、告警和 CSV 导出。[S07] | 与本需求最直接接近的轻量参考之一 | 参考输入表、公式解释与异常提示；以本项目独立定义的参考点和算法对照，不能默认所有 P1dB 结果应一致 |
| **RFCascade（Jason Durbin）** | 原作者公开了 JavaScript 射频级联计算器源码；授权说明允许教育与非商业用途，商业用途需联系作者。[S08] | 可观察交互思路，但“源码公开”不等于可不受限制商业复用 | 原则上不拷贝其实现；独立编写核心算法、界面及图形 |
| **scikit-rf** | Python 射频网络库，官方教程包含 Network、S 参数及网络级联；仓库采用 BSD 三条款式许可。[S09][S10][S11] | 适合后续 Touchstone、频率响应和失配分析，不是开箱即用的完整中文预算与导出软件 | 暂列增强依赖，待第二阶段引入；保留许可证要求 |

**结论：**已有工具证明“射频级联计算”本身有成熟实现，但本次核查到的材料不足以证明其中某一个可以直接满足“中文本地界面 + 可重算 Excel + 类型化器件图形 + 原生 draw.io + 可靠 Visio 编辑”的全部组合要求。因此建议独立建设轻量工具，复用通用库，而不是寻找一个现成项目改名交付。

商业软件的具体价格、采购资格和授权细则不在本文中推测。需要作为正式验证基准时，应在实际使用环境中确认对应版本与授权。

## 0.3 调研发现的关键实现陷阱

| 问题 | 核查结论／推导 | 必须落实的设计 |
|---|---|---|
| Excel “有公式”是否意味着导出时已算出结果 | openpyxl 官方明确表示不负责计算公式。[S16] | 真实公式、自动重算设置、静态结果快照和实际 Excel 重算测试分别处理 |
| draw.io 能否作为稳定 VSDX 转换器 | 当前官方导出格式列表未列 VSDX；官方仓库存在 VSDX 导出移除的记录。[S21][S23] | 不依赖最新版 draw.io 一键导出 VSDX；原生 VSDX 使用独立可选后端 |
| SVG 是否等于 Visio 原生可编辑图 | VSDX 本身是带关系、页面和图形结构的文档格式，不是 SVG 改后缀。[S24] | 明确区分矢量图素材、原生节点及粘接连接器，不作跨软件编辑保真保证 |
| Graphviz Python 包是否包含完整布局环境 | Python `graphviz` 文档要求安装系统 Graphviz 并使可执行程序可访问。[S19] | 安装诊断检查 `dot`；缺失时使用明确标注的简单布局降级 |
| 普通可编辑表是否自动支持可靠拖拽排序 | Streamlit 动态增删行与排序行为存在限制，编辑器状态需按其接口处理。[S14] | 首版使用稳定 ID 和显式上移／下移／重排，不假定原生拖拽已解决 |
| 系统 P1dB 能否由“最弱一级”直接给出 | 级联多个非线性级会累计压缩；仅有各级 P1dB 不能唯一确定整条 AM/AM 曲线 | 最弱一级只作定位提示；正式估算给出明确模型并求系统总压缩 1 dB 的根 |
| 温度字段是否直接替换所有公式中的 290 K | NF 的参考温度、输入源温度和器件物理温度不是同一个量；`rfbudget` 文档也明确其 290 K 参考。[S03] | 三种温度概念分别保存和解释，避免输出错误噪声底 |

## 0.4 推荐路线及不选择的路线

**推荐路线：**Python 计算内核、Streamlit 本地中文 UI、openpyxl 工作簿、Graphviz 布局、统一图形场景、独立 SVG 与 draw.io 渲染器；原生 VSDX 作为经验证后开启的可选能力。

不选择“全部画成 Graphviz 默认矩形”：无法满足器件功能符号要求。不选择“Excel 只导出静态 DataFrame”：修改输入不会联动，弱化原图中可编辑计算文件的价值。不选择“依赖某个商业软件作为后端”：会给部署和授权增加基础门槛。不选择“先做拖拽画布再补公式”：模型约定和导出兼容才是前置风险。

## 0.5 技术验证应先于大规模界面开发

最先完成三个小型技术验证（spike）：

1. 用同一条三阶段链路，核对 Python 与实际 Excel 重算后的增益、NF、IP3、压缩模型结果。
2. 生成包含放大器、滤波器、混频器及 LO 支路的 `.drawio`，确认符号不是单张图片，文本可改、节点可移、连接线跟随。
3. 在目标 Visio 环境验证可选原生 VSDX 路线；没有通过就禁用该导出，不耽误必需的 SVG、draw.io 和说明文件。

# 一、项目目标

## 1.1 原始目标保留

**【原图明确】**项目名称为 `RF-Link-Calculator`。开发中文界面的射频链路计算工具，用户填写链路输入功率和各级器件参数后，应能自动计算关键指标，生成可编辑 Excel，自动生成与器件类型对应的链路框图，导出 SVG、draw.io，并提供 Visio 兼容方案。项目需本地运行，交付完整可维护源码、README、示例数据和测试用例。

**【目录明确】**必须覆盖累计增益及输出功率、Friis 噪声系数、系统 P1dB／压缩、IP3／IM3、动态范围、逐级表、汇总卡片、告警、Excel、框图、示例、目录结构与验收。

## 1.2 第一版范围

**【补充设计】**第一版定义为：在统一参考阻抗、窄带标量参数和选定工作状态下，对**单条有序串行主信号路径**进行工程预算。

| 包含 | 明确暂不包含 |
|---|---|
| 接收、发射、上变频、下变频、其他链路标签 | 无线传播环境、地形、覆盖范围、天线阵列波束仿真 |
| 单频工作点和各级工作频率传播 | 全频带大信号谐波平衡、完整杂散搜索 |
| 放大、衰减、滤波、传输、变频及多端口器件的选定等效路径 | 任意分支网络、多源合路、反馈环路和相干合成 |
| 线性功率、噪声、IP3、弱非线性 IM3、模型化压缩 | 调制波形级 EVM、ACLR、AM/PM、记忆效应与热效应 |
| 可保存的 JSON 项目、可重算 Excel、编辑图形文件 | 自动从任意数据手册提取并保证正确的器件数据库 |

第一版不能把“标量预算”包装成“实物一定达到该性能”。数据手册典型值、频率和偏置条件不一致时，结果只代表输入参数对应的设计场景。

## 1.3 必需能力与增强能力

| 层级 | 内容 |
|---|---|
| **V1 必需** | 原图全部核心功能、可追踪的公式、中文 UI、字段校验、逐级与系统指标、输入保存、Excel 真实公式、类型化 SVG／draw.io、Visio 说明、自动测试和示例 |
| **V1 条件开启** | 原生 `.vsdx`：仅在指定导出后端和目标软件版本通过编辑性验收后开启 |
| **V1.1 增强** | 实测 AM/AM 表、频率扫描、参数扫描、对比两条链路、器件库与来源管理、布局位置回读 |
| **V2 独立扩展** | S 参数失配、Touchstone、复杂分支与阻塞干扰、混频杂散矩阵、ADC/DAC 动态范围、波形仿真 |

分期是为界定实现顺序，不代表删除截图已有功能。P1dB、IP3、动态范围、Excel、SVG、draw.io 都属于 V1，而不是以后再补的占位项。

## 1.4 交付物清单

目标软件正式交付时应包含：完整源码、中文 `README.md`、锁定的依赖清单、运行与诊断脚本、至少六类示例、测试与测试说明、公式／模型说明、示例导出文件及第三方依赖说明。

单次用户导出建议生成：

```text
项目名称_链路名称_导出时间/
├── 链路输入.json
├── 链路计算.xlsx
├── 链路框图.svg
```

# 二、技术方案要求与总体架构

## 2.1 保留技术栈并明确分工

| 技术 | 要求来源 | 推荐职责与限制 |
|---|---|---|
| Python 3.11+ | 【原图明确】 | 计算、数据校验、文件生成；以一组实际测试过的版本作为发布基线 |
| Streamlit | 【原图明确】 | 中文本地浏览器 UI；不把业务数据直接绑死在 widget 状态里 |
| pandas | 【原图明确】 | 表格视图和导入整理；不把 DataFrame 当成唯一领域模型 |
| numpy | 【原图明确】 | 数值转换、稳定指数计算和批量计算 |
| openpyxl | 【原图明确】 | XLSX 样式、表格、数据验证和公式写入；不承担公式求值。[S16] |
| Graphviz + SVG | 【原图明确】 | Graphviz 负责布局；自有 SVG 渲染器负责器件符号和中文文本 |
| mxfile XML | 【原图明确】 | 生成 draw.io 原生对象、分组、端口和连接线，而非单张嵌入图片。[S20][S22] |
| pytest | 【原图明确】 | 单元、集成、数值回归测试 |
| 标准库 dataclasses／enum／json | 【补充设计】 | 领域模型、参数状态、序列化；避免不必要的框架耦合 |
| 可选 pywin32／vsdx | 【补充设计】 | 原生 Visio 导出验证分支；不是基本运行依赖。[S25][S26][S27] |
| 可选 scikit-rf | 【补充设计】 | 后续 S 参数与网络分析扩展。[S09][S10] |

依赖版本不能简单写“全部 latest”。开发验证通过后生成明确锁定文件并记录 Python、Streamlit、openpyxl、Graphviz 程序等实际版本。第三方库是否支持所选 Python 小版本，属于环境验证项，不在本文虚构兼容性测试结果。

## 2.2 总体分层

```text
presentation/   Streamlit 页面、输入表、结果卡片、错误提示
        ↓
application/    用例编排、项目提交、计算任务、导出任务
        ↓
domain/         Project、Stage、Metric、Assumption、ValidationIssue
        ↓
engine/         单位、频率、增益、噪声、IP3、压缩、动态范围

application/ ──→ diagram/       DiagramScene、布局、符号、端口
application/ ──→ exporters/     Excel、SVG、draw.io、可选 VSDX
application/ ──→ persistence/   JSON、迁移、原子保存、备份
```

计算引擎不得导入 Streamlit，不得访问 session_state，不应为了算 NF 去读取 Excel。导出器不得各自实现不同版本的业务定义。图形层只消费经过确认的数据与结果，不自行猜测器件参数。

## 2.3 单一可信输入与一致结果

规范化后的 `Project` 是输入事实来源；`ResultBundle` 是该输入快照的计算结果；`DiagramScene` 是图形结构来源。UI、Excel 快照、SVG 标签、draw.io 标签必须来自同一个 `ResultBundle`。

Excel 中的可重算公式是计算引擎的第二种实现，因此需要单独对照测试，而不是认为“引用了同一份输入就不会错”。

每次提交计算时生成：

```text
input_hash = SHA256(规范 JSON：稳定字段顺序、明确单位、无 NaN/Infinity)
formula_version
schema_version
compression_model_version
created_at
```

不把生成时间放入参与计算的输入散列；修改备注是否影响散列应分开处理：建议 `calculation_hash` 仅涵盖计算输入，`project_hash` 涵盖全部项目内容。

输入改变后旧结果标为“未更新”，禁止把旧图和新表组合导出。导出过程中再修改输入，不影响已经冻结的导出快照。

## 2.4 本地运行、持久化与安全

默认仅监听 `127.0.0.1`。用户数据写入项目配置的数据目录；程序目录与数据目录分离。不硬编码某位用户的盘符。界面可选择工作目录，但路径必须校验，保存应先写临时文件再原子替换，保留有限数量备份。

第一版采用 JSON 项目文件即可，不必引入数据库、登录系统或云服务。软件启动不自动上传链路参数。运行所需前端资源不得依赖未经说明的外部 CDN；器件图片、图标和样例随项目提供可合法分发的自有资源。

导入设置大小上限、行数上限和文本长度上限；禁止执行输入中的 Python、Excel 宏、XML 实体或任意 shell 命令。Graphviz 使用参数列表调用与超时，不将器件名称拼接进 shell 命令。名称进入 XML、SVG 或 Excel 时分别按格式转义。

## 2.5 能力探测而不是静默失败

# 四、计算功能与公式

## 4.0 统一物理约定

**【原图明确】**功率以 dBm 表示；增益、损耗、噪声系数以 dB 表示；内部须正确转换；理论线性计算与考虑压缩的估算必须区分。

**【补充设计】**第一版采用匹配条件下的功率增益。输入功率为主路径输入参考面的可用／匹配传输功率；在统一匹配假设下不再区分可用增益、传输增益与工作功率增益。存在明显失配时，结果应标注不适用，不能只把任意 S21 dB 当作全条件增益。

设主链共有 n 个启用器件：

| 符号 | 含义 |
|---|---|
| $g_i$ | 第 i 级小信号功率增益，dB；损耗用负值 |
| $G_i=10^{g_i/10}$ | 第 i 级线性功率增益 |
| $g_{<i}=\sum_{j<i}g_j$ | 第 i 级之前的累计增益，dB |
| $A_{i-1}=10^{g_{<i}/10}$ | 第 i 级之前的线性累计增益，$A_0=1$ |
| $NF_i$、$F_i=10^{NF_i/10}$ | 第 i 级噪声系数的 dB 与线性表达 |
| $T_0=290\,K$ | 本项目采用的噪声系数参考温度 |
| $T_s$、$T_{p,i}$ | 输入源等效噪声温度、器件物理温度 |
| $B_n$ | 等效噪声带宽，Hz |
| $k_B=1.380649\times10^{-23}\,J/K$ | 玻尔兹曼常数；数值为 SI 定义的精确值。[S13] |

全部中间结果使用双精度，不在每级先四舍五入。显示默认保留 2～3 位小数；导出计算值保留完整可用精度。计算不得把 dBm 相加作为功率求和。

参考温度 T0 在第一版固定为 290 K，不是可以与源温度一样随意调整的输入项；改变 NF 参考温度需要同时转换对应噪声因子。常规手动 NF 在本版要求非负；特殊噪声定义应增加相应模型，不对负 NF 自动取绝对值或强制归零。

### 单位转换

$$
P_{mW}=10^{P_{dBm}/10},\qquad
P_{dBm}=10\log_{10}(P_{mW})
$$

$$
P_W=10^{(P_{dBm}-30)/10},\qquad
r=10^{r_{dB}/10}
$$

同一阻抗条件下的幅度比才使用 $20\log_{10}$。本项目增益、NF、功率和 IP3 级联公式使用功率量，不能混入幅度换算。

## 4.1 各级累计增益及输出功率

**【目录明确】**必须计算各级累计增益与输出功率。

$$
g_{\le i}=\sum_{j=1}^{i}g_j
$$

$$
P_{in,i}^{lin}=P_{in,0}+g_{<i}
$$

$$
P_{out,i}^{lin}=P_{in,0}+g_{\le i}
$$

$$
g_{sys}=\sum_{i=1}^{n}g_i,\qquad
P_{out,sys}^{lin}=P_{in,0}+g_{sys}
$$

例：输入 −60 dBm，三个器件增益为 −2、20、10 dB，逐级输出为 −62、−42、−32 dBm，累计增益为 −2、18、28 dB。

输出表必须同时给出“本级输入”“本级输出”和“累计增益”，方便判断是否把某一级增益加了两次。噪声参数缺失不影响上述功率结果；增益缺失会影响该级及其后的参考点换算。

空链路建议显示“尚未添加器件”。在内核中可以将其定义为恒等传输（增益 0 dB、输出等于输入），但界面不能把空项目误标为完整的射频系统分析。

## 4.2 级联噪声系数 NF：Friis 公式

**【目录明确】**必须实现 Friis 级联噪声系数。TI 和 MathWorks 的预算工具将 Friis 类预算作为基础分析方法。[S03][S07]

$$
F_{sys}=F_1+\frac{F_2-1}{G_1}
+\frac{F_3-1}{G_1G_2}+\cdots
+\frac{F_n-1}{G_1\cdots G_{n-1}}
$$

等价的便于循环实现形式为：

$$
F_{sys}=1+\sum_{i=1}^{n}\frac{F_i-1}{A_{i-1}},
\qquad NF_{sys}=10\log_{10}(F_{sys})
$$

每一级新增的输入参考噪声贡献：

$$
\Delta F_i=\frac{F_i-1}{A_{i-1}}
$$

该贡献可以用于“主要噪声贡献器件”的解释，但不要把 $10\log_{10}\Delta F_i$ 直接标为可相加的“NF dB 贡献”。推荐显示 $\Delta F_i$ 的线性值、等效噪声温度贡献或对总附加噪声的比例。

### 4.2.1 无源器件的 NF

对匹配、处于物理温度 $T_p$、损耗 $L=1/G\ge1$ 的热无源等效二端口：

$$
T_e=(L-1)T_p
$$

$$
F=1+(L-1)\frac{T_p}{T_0}
$$

只有当 $T_p=T_0$ 时，才得到 $F=L$ 与“NF 的 dB 值等于插入损耗 dB 值”。该关系由热噪声等效模型推得，不能扩展成“所有负增益器件 NF 都等于损耗”。混频器、受偏置器件以及终端条件不同的多端口器件需要独立模型或有效测量参数。

### 4.2.2 温度、噪声底与 SNR

系统附加等效输入噪声温度为：

$$
T_{e,sys}=T_0(F_{sys}-1)
$$

输入参考的总噪声功率为：

$$
N_{in,eq,W}=k_B B_n(T_s+T_{e,sys})
$$

输出噪声功率为：

$$
N_{out,W}=N_{in,eq,W}\prod_i G_i
$$

$$
N_{out,dBm}=10\log_{10}\left(\frac{N_{out,W}}{10^{-3}}\right)
$$

$$
SNR_{out}^{lin}=P_{out,sys}^{lin}-N_{out,dBm}
$$

当 $T_s=T_0$ 时，可以化为熟悉的：

$$
N_{out,dBm}=-173.975187+10\log_{10}(B_n)+NF_{sys}+g_{sys}
$$

其中 −173.975187 dBm/Hz 是本文按 $k_BT_0$ 计算的 290 K 值，不应同时又加一遍温度修正。源温度不等于 290 K 时，使用前面的 $T_s+T_e$ 一般式。

**错误示例：**把温度改成 100 K，然后直接用 $k\times100\times B\times F_{290}$ 计算输出噪声，会错误地把接收机自身附加噪声一同缩小。正确做法是保持已给定的 $T_e$，只改变输入源那一项。

### 4.2.3 带宽、通带和模型有效性

信号带宽与等效噪声带宽分开保存。默认相等代表平坦通带与等效矩形噪声带宽近似；若后续加入实际滤波曲线，再通过频率积分求有效噪声带宽。

单点增益、单点 NF 不能证明整个信号带宽内都平坦。器件通带不足或频率数据超范围时，保留标量计算结果的同时标注“模型条件未满足”；严格模式可阻止发布为已验证报告。

NF 属于此处的小信号噪声模型。**不得把每级增益直接换成压缩后的增益重新套 Friis，然后声称得到准确的大信号 NF。**第一版不提供未经验证的非线性噪声仿真。

## 4.3 系统 P1dB 与压缩分析

**【目录明确】**必须有 P1dB 与压缩分析。**【原图明确】**必须区分线性结果与压缩估算。

### 4.3.1 先统一输入、实际输出和线性外推输出的定义

设某器件小信号增益为 $g_0$，输入 1 dB 压缩点为 $IP_{1dB}$。在该输入下，**实际**输出比小信号直线低 1 dB，因此：

$$
OP_{1dB}^{actual}=IP_{1dB}+g_0-1
$$

$$
IP_{1dB}=OP_{1dB}^{actual}-g_0+1
$$

而对应的线性外推输出为：

$$
OP_{1dB}^{linear\ reference}=IP_{1dB}+g_0
$$

这是由 1 dB 压缩定义直接推得的换算。很多表格使用“输出参考阈值”的简化口径；导入时必须询问该数值是实际输出还是线性外推输出，不能一概按同一个公式转换。MathWorks 的器件与非线性模型文档也分别提供输入／输出压缩参数及更完整的非线性建模选项。[S05][S12]

**开发规则：**内部统一保存输入参考 $IP_{1dB}$；保留原始输入值、原参考定义与转换记录。UI 不允许一个没有说明的“P1dB”列同时容纳各种口径。

### 4.3.2 阈值筛查不等于系统压缩点

将各级输入 P1dB 按前级小信号增益折算回链路入口：

$$
q_i=IP_{1dB,i}-g_{<i}
$$

$\min q_i$ 可以帮助定位容易压缩的级，但一般不能直接称为整条链路的“系统 1 dB 压缩点”。多个器件各自压缩不足 1 dB 时，整条链路也可能已经合计压缩 1 dB。

同样，不能根据 IP3 自动减去一个固定常数生成 P1dB。特定多项式模型可以产生特定关系，但不是所有放大器、混频器和工作状态的普遍规律。

### 4.3.3 第一版推荐的工程压缩模型

当只有小信号增益与 P1dB、没有完整 AM/AM 测量曲线时，采用**以 P1dB 为锚点的单调软饱和模型**。它借鉴 Rapp 类平滑饱和模型的结构，但下式的参数化与默认值是本文的工程设计，不是某个器件的已识别物理模型。现有非线性建模工具同时提供多项式、Rapp 类和查表模型，也说明模型选择不能由一个 P1 数值唯一决定。[S12]

对第 i 级，输入 $x$ 用 dBm 表示，定义其压缩量：

$$
C_i(x)=\frac{10}{p_i}\log_{10}\left[
1+\left(10^{p_i/10}-1\right)
10^{p_i(x-IP_{1dB,i})/10}
\right]
$$

$$
y_i=x+g_i-C_i(x)
$$

其中 $p_i>0$ 控制压缩形状，第一版默认所有非线性级使用 $p=2$，高级设置可以调整并记录该假设。建议第一版界面把可配置范围限制在经测试的 1～10，而不是接受任意极端参数。

该模型满足：低输入时 $C_i\to0$；输入等于本级 $IP_{1dB}$ 时 $C_i=1$；输出随输入单调增加并逐渐饱和。明确理想线性的级使用 $C_i=0$。

**不能作出的推论：**独立填写的 IP3 与此压缩曲线未必来自同一个自洽的波形非线性模型。尤其默认 p=2 的软饱和曲线，不能自动用于推导用户填写的三阶互调系数。因此界面应说明“IP3 是独立弱非线性预算；压缩是独立 AM/AM 工程估算”。

### 4.3.4 顺序传播与系统求根

```text
x = 链路入口输入功率
逐级执行：
    本级输入 = x
    本级压缩 = 模型(x, 本级IP1dB, p)
    本级输出 = x + 本级小信号增益 - 本级压缩
    x = 本级输出
系统总压缩 = 入口功率 + 系统小信号增益 - 最终实际估算输出
```

系统输入 1 dB 压缩点为以下方程的根：

$$
D(P)=P+g_{sys}-P_{out}^{estimate}(P)=1
$$

每次计算 $D(P)$ 都必须完整顺序传播，不能让后级继续使用已经失真的“理论线性前级输出”。求根建议使用确定性二分法：从折算阈值构造初始区间，检查两端确实夹住根，必要时按规定步长扩张；达到容差或迭代上限即结束。未夹住根应返回明确状态，不输出随意端点。

建议初始区间为 $[\min(q_i)-80,\max(q_i)+20]$ dBm，最大 80 次迭代，停止条件为输入区间宽度小于 $10^{-6}$ dB。该区间只是实现启发式，不可省略夹根检查。处于限制范围外时，记录“在设定搜索范围内未找到”。

系统实际输出压缩点：

$$
OP_{1dB,sys}^{estimate}=IP_{1dB,sys}^{estimate}+g_{sys}-1
$$

所有系统 P1dB 卡片与导出标签都必须包含“模型估算”。

### 4.3.5 同一 p 时的闭式交叉检查

对上述特定软饱和模型，若所有非线性级的 p 相同、其他级理想线性，可以推得：

$$
IP_{1dB,sys}^{estimate}
=-\frac{10}{p}\log_{10}\left[
\sum_{i\in nonlinear}
10^{p(g_{<i}-IP_{1dB,i})/10}
\right]
$$

这是**该模型和同一 p 条件下**的闭式结果，不是普遍适用于所有实物链路的 P1dB 级联公式。可用它做 Python 二分法和 Excel 求解表的独立交叉检查。

例如两个 0 dB 增益、各自输入 P1dB=0 dBm、p=2 的器件，系统估算输入 P1dB 为 −1.505150 dBm，而不是最小单级阈值 0 dBm。本文已对该结果进行数值核算。

### 4.3.6 数值稳定性与缺失规则

计算 $\log(1+e^z)$ 使用稳定形式 `max(z,0)+log1p(exp(-abs(z)))`，不要直接在高输入时计算可能溢出的巨大指数。

任何参与主链的器件若压缩参数为未知，系统真实完整模型就不成立。默认返回“压缩参数不完整”。可以提供“仅已知器件的条件估算”，但必须是单独的诊断结果，不能作为完整系统 P1dB 放在主汇总卡上。

深压缩区仅显示醒目估算警告；示例可将总压缩大于 3 dB 作为警告阈值，这是软件提示策略，不是模型精度的已验证边界。单音 CW 压缩模型不等于复杂调制信号的平均功率压缩；PAPR、EVM、ACLR 的求解不属于第一版。

### 4.3.7 实测数据的后续路线

V1.1 引入 `[Pin_dBm, Pout_dBm]` AM/AM 数据，校验输入顺序、单调性、低功率增益与范围。优先采用单调插值；范围外必须明确选择“不外推”或经过验证的外推策略。不得拿两个测点随意拟合整个饱和区。

有实测曲线时，系统求根框架不变，只替换每级传递函数。这是把“估算器”升级为“测量模型级联”的清晰扩展点。

## 4.4 系统 IP3 与 IM3 分析

### 4.4.1 参考点换算

$$
IIP3_i=OIP3_i-g_i
$$

$$
OIP3_{sys}=IIP3_{sys}+g_{sys}
$$

IP3 使用小信号外推直线，换算中没有 P1dB 定义中的额外 1 dB 项。

### 4.4.2 相干最坏相位的级联公式

令 $P_{IIP3,i}$ 为各级 IIP3 的线性功率，统一用 mW，则：

$$
\frac{1}{P_{IIP3,sys}}=
\sum_{i=1}^{n}\frac{A_{i-1}}{P_{IIP3,i}}
$$

再转换为 dBm。ADI 的级联推导明确讨论了互调电压同相相加的最坏情况以及功率单位要求。[S28]

第一版默认采用这一**弱非线性、相干最坏相位**预算口径。不同器件失真可能相消或不同频率受到不同抑制，不能将本式宣称为任意链路的精确结果。不引入“随机相位功率和”选项，除非单独实现并测试另一套明确模型。

显式理想器件贡献为 0；未知器件导致系统 IP3 完整度不足。全链路显式理想时显示“模型内无三阶失真／IP3 无有限值”，不用 `999 dBm` 伪造数值。

### 4.4.3 双音每音功率与总功率

等功率双音时：

$$
P_{total}=P_{tone}+10\log_{10}2
=P_{tone}+3.0102999566\ dB
$$

IP3、IM3 计算使用**每个音的功率**。界面同时显示每音与双音总功率，输入框必须标明当前编辑哪一个。输入 Pin 默认仍为单音 CW 值；切换双音分析不能悄悄把同一个数从单音改为总功率。

两音频率为 $f_1$、$f_2$ 时，近带三阶互调频率为 $2f_1-f_2$、$2f_2-f_1$。本版只在两基波及相关 IM3 所经链路可用同一组有效标量参数近似时输出预算，否则提示需要频率选择性模型。

### 4.4.4 三阶互调功率与 dBc

在小信号外推成立时，每个 IM3 分量的输出功率为：

$$
P_{IM3,out}=3P_{tone,in}+g_{sys}-2IIP3_{sys}
$$

等价形式：

$$
P_{IM3,out}=3P_{tone,out}-2OIP3_{sys}
$$

有符号相对电平：

$$
IM3_{dBc}=P_{IM3,out}-P_{tone,out}
=-2(OIP3_{sys}-P_{tone,out})
$$

若显示“互调抑制度”，应使用上式相反数并标正值 dB。不要把 −60 dBc 与“抑制 60 dB”在同一列无说明混用。

IM3 公式接近强压缩时失效。压缩预警触发后，界面将其标为“弱非线性外推，不代表大信号实测”。不得把公式外推产生的异常高互调当成可信频谱。

双音分析的有效性检查必须使用其自身的每音功率与双音总平均功率，不能借用另一个较低输入功率的主 CW 分析“未压缩”结论。以双音总平均功率对照单音 P1 只能做粗略工作点筛查，不等于预测双音或调制波形的真实压缩；缺少相应模型时明确保留这一限制。

### 4.4.5 频率选择性限制

滤波器可能对基波、阻塞信号和 IM3 施加不同增益；混频器还会改变频率映射。仅用通带插损计算一个整链 IP3，不能预测全部阻塞与杂散情形。ADI 的分析中也专门引入选择性来修正互调预算。[S28]

第一版只做注明条件的同通道近带分析。一般阻塞场景、不同频点衰减、镜像带噪声和混频杂散矩阵列入后续扩展，不以一个含糊的“杂散分析完成”按钮掩盖范围限制。

## 4.5 动态范围指标

**【目录明确】**必须提供动态范围指标。动态范围没有一个可以脱离带宽、下限定义和上限定义使用的统一数值，因此至少分成以下几项。

### 4.5.1 噪声底与灵敏度

$$
Sensitivity_{in}=N_{in,eq,dBm}+SNR_{required}+L_{implementation}
$$

其中所需 SNR 与实现损失是用户设计目标。界面说明带宽和温度口径。不能把“噪声底”直接叫“灵敏度”，也不能将某种调制需要的 SNR 固定为所有链路的要求。

### 4.5.2 压缩约束动态范围

$$
P_{upper}=IP_{1dB,sys}^{estimate}-Backoff
$$

$$
DR_{compression}=P_{upper}-Sensitivity_{in}
$$

结果标签为“基于模型 P1dB 与指定回退量的输入动态范围”。该指标不代表器件不会损坏；绝对最大额定输入功率需要独立检查。

### 4.5.3 三阶无杂散动态范围 SFDR3

将每个 IM3 分量等于同一分析带宽内的输出噪声底作为边界，可推得输入每音上限：

$$
P_{tone,max}=
\frac{N_{in,eq,dBm}+2IIP3_{sys}}{3}
$$

$$
SFDR_3(B_n)=\frac{2}{3}
\left(IIP3_{sys}-N_{in,eq,dBm}(B_n)\right)
$$

这里的 SFDR 下限是噪声底，并不是上面的“满足指定 SNR 的灵敏度”。如需“满足指定 SNR 的双音可用跨度”，另计算 $P_{tone,max}-Sensitivity_{in}$，并明确其名称。

使用 1 Hz 噪声谱密度时，可以表达带宽归一化指标，单位写成 $dB\cdot Hz^{2/3}$；不能把它与某个实际带宽内的 dB 结果并列而省略单位差别。固定其他条件时，噪声带宽扩大 10 倍，SFDR3 减少约 6.666667 dB，是一个重要测试不变量。

### 4.5.4 指标有效性

系统 NF 缺失则不显示可靠噪声底、灵敏度和 SFDR；IP3 缺失只影响 IP3/IM3/SFDR；压缩参数缺失只影响压缩动态范围。不同指标独立评估可用性。

若计算得到负动态范围，保留负值并告警“该条件下上下限无重叠”，不要截成 0 后隐藏问题。双音 SFDR 也不能替代复杂调制系统的 EVM 或邻道泄漏指标。

## 4.6 变频链路的频率传播

**【补充设计】**截图包含上、下变频链路类型，因此需要最小可用的频率传播，而不能所有级都显示同一个 RF 频率。

每个混频器由用户选择目标输出关系，例如：

$$
f_{out}=f_{in}+f_{LO}
$$

或：

$$
f_{out}=|f_{in}-f_{LO}|
$$

记录高侧／低侧关系及频谱是否翻转。LO 是混频器辅助端口，不作为主信号串行器件混入 Friis 求和，也不把 LO 驱动功率加到所选 IF 输出功率。

例：2.4 GHz 输入、2.3 GHz LO、选择差频，输出为 100 MHz。混频器后的器件范围检查使用 100 MHz，而不是 2.4 GHz。

带宽跨越零频、镜像带混叠以及基带 I/Q 处理超出本版普通窄带实信号预算。SSB 与 DSB NF 口径必须保存；**不得无条件相差 3 dB 后自动转换**。无法确认与所选链路噪声定义一致时，停止该部分噪声预算并要求提供有效参数。

## 4.7 计算引擎的结果状态

每项指标均保存 `value + unit + status + model + assumptions + dependencies`。建议状态为：有效、模型估算、未知、理想无有限值、不适用、输入无效、计算失败。

比如“NF 未知，但总增益有效”和“IP3 有效，但当前强压缩条件下 IM3 外推不适用”都是正常可表达状态。禁止用同一个 `0`、空字符串或红色破折号替代所有原因。

## 4.8 数值稳健性

累积增益优先在 dB 域相加，IP3 倒数项与大动态范围噪声贡献可以使用对数域累加。接近 0 dB 的 NF 计算 `F-1` 时优先采用 `expm1(NF*ln(10)/10)`，避免两个相近浮点数相减损失精度。显式理想或零附加噪声项独立处理，不对零项直接取对数。

所有字段与累计结果检查有限性。若极端参数导致线性转换溢出、下溢或非正噪声总温度，应返回数值定义域错误，注明受影响指标，而不是继续产生 `NaN`、静默截断或随机采用一个上限值。发布配置应列明经过测试的工程数值范围；范围警告与物理上不可能的判断分开，不能把软件实现上限说成器件物理定律。

## 5.3 图表设计

第一版可以提供三个独立图：逐级信号与噪声电平、累计增益／NF 指标切换图、输入扫描的线性输出与压缩输出曲线。

采用清晰轴标签和单位。dBm 与 dB 不在同一数轴无说明叠加；必要的双轴必须显示各自单位。输入扫描仅在完整模型可用时开启，范围自动覆盖工作点和估算压缩点，同时允许用户限制范围。

图形颜色不能是判断状态的唯一手段；错误、未知、估算都需要文字或图标说明。

| W012 | 修改输入后结果尚未重新计算 | 禁止按“最新结果”导出 |
| W013 | Graphviz／Visio 后端缺失 | 说明降级能力与缺失格式，不伪装成功 |
| W014 | 动态范围为负 | 提示设计约束冲突，保留原始负值 |
| W015 | NF/IP3 与 P1 数据来自不同频点、温度或偏置 | 提醒条件不一致，不自动拼成“保证值” |

交叉字段如 OIP3 与 OP1 的数值关系宜作为提示，而不是硬编码某个固定差值作为合法性条件。

# 六、Excel 导出要求

## 6.1 “可编辑”必须有明确验收含义

**【原图明确】**生成可编辑 Excel 链路计算文件。**【补充设计】**本计划采用较强定义：用户在 Excel 中修改输入功率、器件参数、启用状态或整体器件顺序后，公式结果可以重新计算；不是仅允许改写一张静态结果表。

同时交付一张不随编辑改变的“导出结果快照”，方便没有公式计算引擎的预览器查看原始结果。它必须明确标为历史快照，不能让用户以为修改输入后快照也会变化。

## 6.2 工作簿布局

| 工作表 | 主要内容 | 可编辑性 |
|---|---|---|
| `使用说明` | 项目概况、颜色图例、参考点说明、重算说明、限制、计算版本 | 说明文本；不参与计算 |
| `输入配置` | Pin、频率、信号与噪声带宽、源温度、SNR 目标、回退量、模型参数 | 用户输入区 |
| `器件参数` | 有序器件输入、参数模式、参考点、来源与频率条件 | 用户输入区；整行移动或排序 |
| `逐级计算` | 累计增益、功率、NF、IP3、当前压缩传播、状态列 | 公式区 |
| `系统汇总` | 系统各项指标、适用性、告警、动态范围 | 公式区 |
| `压缩求解` | 根区间检查、展开的迭代、同 p 闭式结果对照 | 公式区；可折叠但不删除 |
| `结果快照` | Python 导出时的数值、输入散列、时间和模型版本 | 静态报告；醒目标明不自动更新 |
| `公式与来源` | 公式、变量、假设、数据来源、指标有效性规则 | 说明区 |

首版不要求 Excel 内嵌 SVG 框图；图形文件随导出包提供即可。以后需要在表中预览，可另加明确标注的预览图片，但不能用预览图片代替 `.drawio` 或 SVG 源文件。

## 6.3 真实公式与 openpyxl 的边界

openpyxl 可以把公式写入单元格，但不会执行这些公式；公式函数名应使用 Excel 文件格式要求的英文名称，参数使用逗号。[S16]

建议设置：

```python
from openpyxl.workbook.properties import CalcProperties

wb.calculation = CalcProperties(
    calcMode="auto",
    fullCalcOnLoad=True,
    forceFullCalc=True,
)
```

这些属性用于请求打开时重算，不能保证任意预览器会计算，也不能替代实际 Excel 验证。[S17] 默认使用 `openpyxl` 方案并提供静态快照；不要修改私有内部属性伪造公式缓存。

若未来明确要求“无需先打开 Excel，读取公式缓存就必须获得正确值”，可以评估 XlsxWriter 的已知结果缓存写入能力，但那仍是写入 Python 已算出的结果，不是该库具备公式引擎。[S18] 此需求变更须同步评估是否允许替换截图优先指定的导出实现。

## 6.4 参数区与行数策略

第一版按最多 200 级预分配输入行和公式行，默认隐藏未使用区域，用户在范围内添加器件或切换启用状态即可参与重算。所有未使用行应明确禁用，不能以“名字为空”猜测其是否参与计算。

“200 级”同时显示在使用说明和导出窗口。超过该范围时由应用重新生成更大工作簿或明确拒绝，不承诺用户任意插入无穷多行都会自动正确维护复杂公式。

器件输入使用一个完整 Excel Table，包含稳定 ID 和所有字段。排序应整表整行进行；同一器件的增益、NF、IP3、P1 不能被分别排序。公式区依据输入区行位置重新计算主链，不在公式中硬编码某个器件名字。

## 6.5 具体公式设计

### 6.5.1 统一命名与列定义

建议命名区域：`Pin_dBm`、`Bnoise_Hz`、`Tsource_K`、`Tref_K`、`RequiredSNR_dB`、`ImplLoss_dB`、`Backoff_dB`。显示标签保持中文，内部名称采用稳定 ASCII 标识。

`器件参数` 第 4 行开始放器件；示例列：

```text
A 顺序        B 启用       C 器件ID      D 名称       E 类型
F 增益dB      G 噪声模式   H 手动NFdB    I 物理温度K
J IP3模式     K IP3参考点  L IP3数值dBm
M P1模式      N P1参考点   O P1数值dBm   P 压缩形状p
```

`逐级计算` 对应行中，C 为有效增益、D 为前级累计增益、E 为累计增益、F 为前级线性增益、G 为本级线性噪声因子、H 为累计噪声因子。第 3 行设为显式初始状态：累计增益 0、累计噪声因子 1、IP3 倒数累积 0、压缩传递初始功率等于 `Pin_dBm`。

### 6.5.2 增益与噪声公式示例

下列为采用上述列约定的公式示例；项目应由公式生成器统一生成并补充状态列。

```excel
C4 = IF(NOT('器件参数'!B4),0,IF(ISNUMBER('器件参数'!F4),'器件参数'!F4,""))
D4 = IF(ISNUMBER(E3),E3,"")
E4 = IF(AND(ISNUMBER(C4),ISNUMBER(D4)),C4+D4,"")
F4 = IF(ISNUMBER(D4),10^(D4/10),"")
H4 = IF(AND(ISNUMBER(H3),ISNUMBER(G4),ISNUMBER(F4)),H3+(G4-1)/F4,"")
```

本级 `G4` 的规则：禁用行或显式理想噪声模式为 1；手动 NF 通过 `ISNUMBER` 校验后为 `10^(NF/10)`；无源热模式在有效增益与温度条件通过后为 `1+(10^(-gain/10)-1)*Tp/Tref_K`；未知或非法输入为空并在状态列记录原因。

**关键点：**必须先判断输入存在且是数值。Excel 可能在算术中把空单元格当成 0，因此不能直接写 `=10^('器件参数'!H4/10)` 来处理可能留空的 NF。

### 6.5.3 IP3 公式

有限 IIP3 规范化后，累计倒数按下式逐行计算：

```text
inv_ip3_cum_i = inv_ip3_cum_prev + G_before_i / 10^(IIP3_i/10)
IIP3_cum_dBm  = -10*LOG10(inv_ip3_cum_i)
OIP3_cum_dBm  = IIP3_cum_dBm + gain_cum_dB
```

显式理想或禁用行的新增项为 0。遇未知行时，累计状态置未知并停止输出完整系统 IP3；不能忽略该行继续当成完整结果。全理想时倒数为 0，应由状态显示“无有限值”，避免 `LOG10(0)`。

### 6.5.4 P1 参考换算与当前压缩

```text
输入参考：        IP1 = 用户值
实际输出参考：    IP1 = 用户值 - 本级小信号增益 + 1
线性外推输出参考：IP1 = 用户值 - 本级小信号增益
```

对每级当前输入 x：

```text
z = LN(10^(p/10)-1) + p*(x-IP1)*LN(10)/10
C = 10/(p*LN(10)) * (MAX(z,0) + LN(1+EXP(-ABS(z))))
y = x + gain - C
```

这些表达式只对已通过状态校验的有限压缩模型使用。禁用或显式理想线性级令 C=0。完整传播顺序与 Python 一致。

### 6.5.5 系统汇总与动态范围

```text
Te_sys       = Tref_K * (F_sys - 1)
Nin_eq_dBm   = 10*LOG10(k_B * Bnoise_Hz * (Tsource_K + Te_sys) / 0.001)
Nout_dBm     = Nin_eq_dBm + Gain_sys_dB
SNRout_dB    = Pout_linear_dBm - Nout_dBm
Sensitivity  = Nin_eq_dBm + RequiredSNR_dB + ImplLoss_dB
SFDR3_dB     = (2/3) * (IIP3_sys_dBm - Nin_eq_dBm)
DR_comp_dB   = IP1_sys_estimate_dBm - Backoff_dB - Sensitivity
```

每个公式外加依赖状态门禁。可显示的数值与状态不能矛盾，例如某级 NF 未知时仍显示一个绿色的总 NF。

## 6.6 Excel 内的压缩点求解

不依赖用户手动“单变量求解”、宏或外部插件。建议把二分法展开为最多 80 行，每行保存：迭代编号、下界、上界、中点、各级中点功率传递、最终输出、总压缩、下一行边界。

每一行的各级中间功率放在独立列中，引用本行上一级结果；不能引用界面当前 Pin 的压缩结果充当搜索中点结果。该结构在 200 级、80 次迭代时约 1.6 万个阶段计算单元，是可明确设计和测试的有限规模，而不是不透明循环引用。

若所有有效非线性级 p 相同，再建立第四章的闭式公式作为对照。两者偏差超过容差时在汇总页告警，帮助发现公式生成错误。

迭代初始区间必须验证是否夹住根。无压缩器件、未知参数、不合法 p、搜索未夹根分别输出不同状态。Excel 中不得用循环计算开关掩盖设计错误。

## 6.7 样式与可用性

用户输入区与公式区采用不同底色，并配文字图例；输入数值、公式、假设与错误的字体／填充风格保持一致。冻结标题与器件标识列，设置筛选、合适列宽、自动换行、数值单位、打印标题行和横向页面。

功率采用 `0.00 "dBm"`，增益／NF 采用 `0.00 "dB"`，频率采用对应单位显示，不把单位直接拼进参与算术的数值单元格。避免给每一个单元格画浓重边框。

可以轻度保护公式区域防误改，但必须允许用户复制和检查公式；工作表保护不是安全机制。用户更改输入后，`结果快照` 顶部仍显示“导出时快照，不随输入更新”，动态页注明“当前 Excel 公式结果”。

## 6.8 导出与导入安全

器件名称以 `=`、`+`、`-`、`@` 开头时按普通文本写入，不能变成公式或外部引用。公式只允许由程序生成；用户备注不是公式来源。CSV 导出同样需要针对表格软件公式注入处理。

首版标准回读格式为 JSON；CSV 可仅导入规定的器件输入字段。任意 XLSX 回读不是第一版必需能力。以后支持 XLSX 回读时，只读明确输入区域，拒绝宏、外链和未经信任的公式输入，不把缓存值视为一定最新。

## 6.9 Excel 验收方法

自动检查 XLSX ZIP 结构、工作表名、输入值、公式存在、单位格式和参数引用。随后在目标 Windows Excel 桌面环境中执行完整重算、保存，再用 `data_only=True` 读取结果与 Python 对比。

可使用独立的受控本地自动化脚本辅助重算，但安装 Excel 和成功调用才算具备此测试环境。没有实际运行过时，报告应写“公式结构测试通过；Excel 重算测试未执行”，不能写“Excel 兼容性全部通过”。

验证情景至少包括改变 Pin、带宽、源温度、前级增益、NF、IP3、P1、禁用器件、整体重排、增加一个器件、删除一个器件和将参数清空。

# 七、原理框图生成与 Visio 兼容

## 7.1 图形目标与边界

**【原图明确】**器件图形与器件功能类型对应，不得全部使用相同矩形。**【目录明确】**包括图形映射、节点标注、连线标注与导出格式。

本项目生成的是**射频系统功能框图**，不是包含引脚编号、封装和 PCB 网络表的完整电路原理图。滤波器可以具有矩形外框，但必须有区别于普通模块的滤波响应图形；混频器、放大器、LO、开关等应有明确不同的几何符号。

## 7.2 类型到符号的映射

| 器件类型 | 图形表达 | 端口与补充标注 |
|---|---|---|
| 放大器／LNA／PA／VGA | 朝主信号方向的三角形；以短标签区分用途 | 输入、输出；可标 G、NF、IP3、P1 |
| 带通滤波器 | 带通响应示意曲线，配过滤器边界 | 输入、输出、通带或工作频率 |
| 低通／高通／带阻滤波器 | 对应低通／高通／陷波响应 | 不使用与带通完全相同的内部图形 |
| 衰减器 | T／π 衰减网络的简化符号或有明显衰减标记的专用图元 | 损耗值，避免显示成正增益 |
| 混频器 | 圆圈内交叉符号 | RF、IF、LO 三端口，LO 从上方或下方进入 |
| 本振 | 圆形源和正弦标记 | LO 频率、驱动功率；辅助支路 |
| 开关 | 简化刀闸／选择通路符号 | 标出当前通路；其他通路不参与主链计算 |
| 电缆／连接线损耗 | 传输线／同轴简化符号 | 可选长度和损耗 |
| 隔离器 | 带单向标记的专用图元 | 明确信号方向 |
| 耦合器 | 主线和耦合线的双线符号 | 所选端口、耦合／直通路径、其他端口终端 |
| 功分器 | 分支 T 形功能符号 | 仅高亮被分析路径，其他端口标明未参与分析 |
| 输入／输出 | 端口箭头或端口节点 | 频率、功率、参考阻抗 |
| 自定义器件 | 通用模块框，但显示具体类型名称和“自定义模型” | 这是允许的例外，不扩散到所有标准器件 |

采用自有简单矢量几何，避免直接复制未知授权或收费 Visio stencil。需要外部符号库时，先核查许可证并记录归属。

## 7.3 统一图形场景

定义与文件格式无关的 `DiagramScene`：

```text
Scene
  canvas: 宽、高、单位、边距
  nodes[]: id、stage_id、类型、位置、尺寸、几何图元、文本、端口
  edges[]: id、源节点/端口、目标节点/端口、折线路径、箭头、标签
  legend: 符号说明、模型说明、参数状态
  metadata: calculation_hash、版本、时间
```

SVG、draw.io 和 VSDX 渲染器共享节点尺寸、端口与文本内容，不各自重新计算布局。这样可以把“SVG 正确、draw.io 错位”缩小为特定渲染器问题。

主链与辅助支路分开：`main_edges` 表示参与级联的顺序，`aux_edges` 表示 LO、终端和注释连接。图形可以出现支路，不代表计算内核已支持任意多分支网络。

## 7.4 布局实现

首选 Graphviz `dot` 负责布局，设置主信号方向从左到右、固定节点预估尺寸、主链边高权重，LO 等辅助边采用不会扰乱主链顺序的约束。Python 包与外部 Graphviz 程序分别安装。[S19]

建议使用 `dot -Tplain` 获取布局而不是把 Graphviz 默认 SVG 直接当最终成品。plain 输出的节点坐标、尺寸使用英寸，需要转换为统一画布坐标。[S29]

若采用 96 像素／英寸的内部显示尺度：

```text
x_center_px = x_inch * 96
node_width  = width_inch * 96
node_height = height_inch * 96
left = x_center_px - node_width/2
top  = (graph_height_inch - y_center_inch)*96 - node_height/2
```

这里需考虑 Graphviz 与 SVG/draw.io 的纵轴方向差异。折线端点最终吸附到符号的实际端口，而不是机械照搬矩形边界；箭头和线条样式由统一渲染器设置。

没有 `dot` 时采用确定性串行布局：按节点宽度与固定最小间距排布，LO 位于对应混频器上方，端点与标签预留空间。这种降级仍应生成合法 SVG 和可编辑 draw.io，但在图中／导出清单中记录布局方式。

## 7.5 中文文本与长链路

图形文字使用 Unicode 与系统可用中文字体回退，不捆绑或输出操作系统字体文件。标注换行由统一文本布局器负责，避免不同后端自行截断。

默认每个器件显示名称、关键参数两至三行；完整参数放详细模式或旁注。连线上优先显示频率、线性功率，压缩值另加“估算”标记，避免在每条短线挤入八项指标。

长链路提供宽画布模式和按阶段分段模式。200 级链路不能被强行缩成一张 A4 的不可读小图；应允许分页／分段并使用带编号的跨页端口。第一版至少提供可缩放宽图和明确的分段导出策略。

## 7.6 SVG 导出

生成标准 `svg`、`g`、`path`、`polygon`、`circle`、`line`、`text`、`tspan` 等原生元素；包含 `viewBox`、物理或像素尺寸、标题与描述；用 `data-stage-id` 保留器件映射。

不要使用依赖浏览器 HTML 布局的 `foreignObject` 作为核心文字，不执行脚本，不加载外部图片，不把整个图栅格化后伪称 SVG。SVG 的文字和矢量路径保留，但其在不同编辑器中的可编辑程度需单独验证。

SVG 主要保证“清晰矢量输出与标准图形结构”，不自动保证 Visio 的原生设备语义、端口与连接器粘接。

## 7.7 draw.io 原生文件实现

draw.io 支持基于 XML 的图形文档，官方也提供 XML 源编辑入口。[S20][S22] 建议生成未压缩的 mxfile，便于版本控制和调试。

最小层级为：

```xml
<mxfile host="app.diagrams.net">
  <diagram id="page-1" name="链路框图">
    <mxGraphModel grid="1" page="1">
      <root>
        <mxCell id="0" />
        <mxCell id="1" parent="0" />
        <!-- 原生器件分组、几何图元、文本、端口、连接器 -->
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

上述只是结构示意，正式导出须填充画布、几何和样式属性。XML 用 ElementTree 等安全方式构建，不用未转义的字符串拼接器件名称。

每个器件是一个原生分组：基础形状、内部符号、文本、必要端口是其子对象。放大器用三角形对象；混频器用圆与交叉线；滤波器用边界和内部响应线；连线使用带 `source`、`target` 的 edge 单元，而不是不关联节点的孤立线段。

端口采用稳定子节点或明确的入／出锚点；主路径从右出左入，LO 单独进入混频器的顶／底端口。连接线设置正交折线样式及端点约束。器件移动、名称修改、重新打开文件后，连线仍应连接原节点。

**禁止方案：**将整张 SVG 作为一个 image 单元塞入 `.drawio`。这种文件虽然能打开，却不满足逐器件编辑。也不能只导出图片然后附一个空 mxfile。

## 7.8 Visio 兼容性的真实边界

### 7.8.1 导出能力矩阵

| 格式 | 本项目保证／目标 | 不能直接承诺的能力 |
|---|---|---|
| `.svg` | 标准矢量图、中文标注、可缩放、可用于支持 SVG 的软件 | 在任意 Visio 版本中自动变成带语义端口的原生器件与连接器 |
| `.drawio` | 在 draw.io 中逐器件编辑、修改文字、移动节点、保存 | Visio 直接打开该格式；最新版 draw.io 稳定转出 VSDX |
| `.vsdx` | 仅在经测试的可选后端中生成原生 Visio 文档 | 没有验证环境时仍保证通用编辑保真 |
| `Visio导入说明.txt` | 说明实际生成了哪些格式、导入方式、编辑限制与验证环境 | 用模糊说明掩盖没有生成真正 VSDX |

当前 draw.io 官方导出列表没有 VSDX，官方仓库有相关功能移除记录。[S21][S23] 因此不把“安装当前 draw.io 后导出 VSDX”作为正式实施步骤，也不依赖未经审计的旧版或第三方在线转换站处理用户链路数据。

### 7.8.2 路线 A：Windows 桌面 Visio 自动化

适用条件：用户具备已安装、可正常使用的桌面 Visio 和相应授权，且运行于用户可交互桌面环境。

通过 Visio 对象模型建立文档和页面，创建原生三角形、圆形、线条、文本与分组，用连接器关联端点并通过 `GlueTo` 等接口建立粘接，再保存 VSDX。Microsoft 文档提供文档创建和单元格粘接接口。[S25][S26]

此后端建议作为独立进程／命令行工具运行，设置超时、异常清理与资源释放，不在 Streamlit 每次重绘时启动 Visio。不能把个人桌面 Office 自动化扩展成未经验证的多用户后台服务。

优点是能够借助 Visio 自身生成结构；代价是依赖 Windows、Visio 环境和实际自动化验证。它不作为跨平台基础依赖。

### 7.8.3 路线 B：模板驱动的 VSDX 文件生成

VSDX 是包含 XML、关系和页面结构的 ZIP/OPC 文档包。[S24] 可评估使用自有合法模板和 `vsdx` 库进行形状克隆、文本替换、位置修改与连接关系构建；该库官方快速入门展示了读取和操作已有 Visio 文件的路线。[S27]

不能由“库能打开某个 VSDX”就推断其已完整支持任意原生图形生成。技术验证必须检查 Shape ID、页面关系、分组、Connects、文本、几何和中文。若模板修改不足以稳定表达所有器件及端口，应延后该路线，不伪造成功。

从零手写完整 VSDX 包属于高风险独立开发，不建议放入第一版必需路径。

### 7.8.4 开启原生 VSDX 的门槛

只有以下项目全部通过，才允许 UI 显示“导出原生 Visio 文件”：目标版本中打开不报修复；每个器件可单独移动；文字可编辑；标准器件有不同符号；连接器随移动保持粘接；LO 端口正确；保存并重新打开后仍正常。

仅仅能 unzip、扩展名正确、页面能显示一张图片，不算通过。

### 7.8.5 `Visio导入说明.txt` 必须写什么

```text
本次已生成：SVG、draw.io（以及实际存在时的 VSDX）。
原生 VSDX 导出状态：未启用／已生成／失败，原因是什么。
经过验证的系统与软件版本：如未验证，明确写“未验证”。
推荐继续编辑：draw.io 文件在 draw.io 中编辑。
SVG 在目标 Visio 中的插入方式须按该版本实际支持情况验证；
插入后可能只是矢量图素材，不保证原生节点、端口或连接器语义。
.drawio 不是 Visio 的原生文件，不能通过改扩展名使用。
不要上传包含敏感项目参数的图到未知在线转换服务。
```

这比简单写“SVG 或 draw.io 导入 Visio 就能继续编辑”更准确，也保留了截图关于必须提供兼容说明、不伪造 VSDX 的原始要求。

## 7.9 图形修改与计算模型回写

用户在 draw.io 中调整位置或修改文字，不自动改变 JSON 计算模型。第一版把图形导出定义为单向生成，明确提示重新生成会覆盖手动排版或建立新文件。

V1.1 可通过 `stage_id` 回读位置与尺寸，但仍不允许仅凭图上改了一段“G=20 dB”就改变计算参数，除非实现了完整、受校验的双向编辑协议。

# 八、示例数据与数值基准

## 8.1 示例不是伪造的数据手册

**【目录明确】**需要示例数据。以下数据均为本文构造的工程演示值，不声称对应任何厂商具体器件，也不代表实测或保证规格。正式器件数据库必须记录真实来源和测试条件。

## 8.3 基准 B：滤波器 + LNA + IF 放大器

条件：单音 Pin=−60 dBm，噪声带宽 1 MHz，源温度 290 K；演示工作频率 100 MHz。双音测试单独使用每音 −40 dBm，不能与单音 −60 dBm 混为同一输入。

| 级 | 类型 | 增益 dB | NF dB | IP3 输入方式 | P1 输入方式 |
|---|---|---:|---:|---|---|
| 1 | 输入滤波器 | −2 | 由 290 K 无源模型得 2 | 明确理想线性 | 明确理想线性 |
| 2 | LNA | 20 | 1.5 | OIP3=25 dBm，即 IIP3=5 | 实际 OP1=10 dBm，即 IP1=−9 |
| 3 | IF 放大器 | 10 | 5 | IIP3=10 dBm | 实际 OP1=15 dBm，即 IP1=6 |

| 结果 | 数值 |
|---|---:|
| 逐级线性输出 | −62、−42、−32 dBm |

| 系统总增益 | 28.000000 dB |
| 系统等效输入附加噪声温度 | 369.167370 K |
| 输入参考总噪声，1 MHz | −110.409210 dBm |
| 输出噪声，1 MHz | −82.409210 dBm |

## 8.4 基准 C：两个 0 dB 增益器件的累计压缩

两个器件均为增益 0 dB、输入 P1dB=0 dBm、p=2，单独测试压缩模块。

系统输入 P1dB 应为 **−1.505149978 dBm**；实际输出为 **−2.505149978 dBm**。入口输入 0 dBm 时，系统输出约为 **−1.682084899 dBm**，总压缩已超过 1 dB。

该例用于否决“系统 P1dB 永远取最弱一级折算阈值”的错误实现，也用于确认 0 dB 增益不会触发除零或跳过器件。

## 8.5 基准 D：单个 3 dB 热无源衰减器

源温度、器件温度均为 290 K，带宽 1 MHz，输入信号 −30 dBm。结果应为：增益 −3 dB，NF 3 dB，输出信号 −33 dBm，输出噪声 −113.975187 dBm。

热平衡条件下，匹配无源器件输出的热噪声仍为 $kT_0B$，信号却衰减 3 dB。该例用于检查是否把输入噪声与器件新增噪声漏算或重复相加。

IP3/P1 是否“理想”必须由示例显式声明，不因为它是衰减器就由程序偷偷赋值。

## 8.6 基准 E：源温度变化而 NF 参考不变

单级增益 10 dB、NF=3 dB（290 K 参考），输入 −50 dBm，带宽 1 MHz。接收机自身等效输入噪声温度保持 288.626071 K。

| 输入源温度 | 输入参考总噪声 | 输出噪声 | SNR |
|---|---:|---:|---:|
| 100 K | −112.703848 dBm | −102.703848 dBm | 62.703848 dB |
| 600 K | −109.111977 dBm | −99.111977 dBm | 59.111977 dB |

这是验证“源温度不应简单乘在整个 NF 上”的专用样例。改温度后，器件 NF 本身仍为 3 dB，除非用户另外提供了随器件温度变化的 NF 数据。

## 8.7 基准 F：下变频示例

建议输入：RF=2.4 GHz、LO=2.3 GHz、差频 IF=100 MHz、信号带宽 10 MHz、Pin=−60 dBm。

链路为：输入滤波器 −1 dB → LNA +20 dB → 混频器 −6 dB → IF 滤波器 −2 dB → IF 放大器 +20 dB。总增益应为 31 dB，线性输出 −29 dBm。

混频器前后频率必须从 2.4 GHz 变为 100 MHz；LO 必须画为独立辅助支路；混频器有效 NF 由示例显式手填并标注 SSB 条件，不从 −6 dB 增益自动推得 NF。此例重点验收频率传播、参数适用性和三端口图形，不以未给全的线性度参数伪造完整 NF/IP3/P1 数值表。

## 8.8 必须随项目补齐的异常示例

至少包含：缺 NF 但增益可算；缺 P1 但线性指标可算；负增益和负 dBm 阈值；全部理想线性；全禁用；强压缩；混频器噪声口径未知；200 级长链路；中文超长名称及 XML 特殊字符。

这些不是供用户直接采用的设计方案，而是软件行为与数据契约的回归测试。

## 8.9 本次已完成的数值核查范围

本次编制过程中使用双精度 Python 独立核算上述 A～E 的相关数值。还生成了固定随机种子的 100 条同 p=2、1～10 级有限压缩链路，对比二分求根与闭式公式；最大输入压缩点偏差约为 $4.3\times10^{-14}$ dB。

这一结果只说明所选模型的两种数学实现一致，不证明该模型与任何实际器件一致，也不意味着 Excel、图形导出或界面已被实际运行测试。正式项目的验收仍须按第十章执行。

# 十、验收标准

## 10.1 验收原则

**【目录明确】**需要验收标准。验收不能只检查按钮是否存在，也不能只比较几张截图。必须同时覆盖数学正确性、错误处理、编辑联动、导出结构与实际软件中的可编辑程度。

所有测试记录写明“执行／未执行”“软件版本”“输入版本”“预期”“实际”“差异与解释”。未执行的商业软件对照不能标为通过。

## 10.2 数值与模型验收矩阵

| 编号 | 测试 | 通过条件 |
|---|---|---|
| N01 | dBm ↔ mW ↔ W、dB ↔ 线性 | 合理数值域内往返误差满足双精度容差；无 10/20 或 30 dB 混淆 |
| N02 | 基准 A、B 逐级增益与功率 | 与第八章值一致，展示舍入不影响中间计算 |
| N03 | Friis 与噪声温度递推 | 与独立手算一致；缺 NF 不产生伪造的 0 dB |
| N04 | 290 K 无源衰减 | 验证 NF=损耗与输出热噪声的特定条件 |
| N05 | 源温度 100／600 K | 与基准 E 一致，有源 NF 不被错误同比缩放 |
| N06 | IP3 输入／输出转换 | 基准数据一致，不出现额外 1 dB 或错误单位 |
| N07 | 双音每音／总功率 | 相差 3.0102999566 dB；IM3 按每音计算 |
| N08 | P1 参考定义 | 实际输出 P1 与输入 P1 换算包含相应 1 dB；线性外推参考单独处理 |
| N09 | 单级压缩锚点 | 输入等于 IP1 时本级压缩为 1 dB |
| N10 | 多级压缩与闭式对照 | 同 p 时与闭式解一致；基准 C 不是错误的 0 dBm |
| N11 | p 不同的级联 | 二分法夹根与顺序传播有效；不误用同 p 闭式结果 |
| N12 | 动态范围带宽关系 | 带宽十倍时理论 SFDR3 减少约 6.666667 dB |
| N13 | 频率转换 | 2.4 GHz / 2.3 GHz 差频为 100 MHz；后级范围按 IF 检查 |
| N14 | 参数缺失与显式理想 | 状态不同，系统指标依赖正确，不把未知当理想 |
| N15 | 增益顺序变化 | 总增益可能不变，但 NF/IP3/P1 按顺序重新计算 |
| N16 | 0／1／50／200 级 | 无崩溃、无截断、状态明确；空链路不误报完整结果 |

建议普通线性预算与独立双精度基准的绝对误差不超过 $10^{-6}$ dB；压缩求根不超过 $10^{-5}$ dB。容差是实现一致性要求，不是实物参数准确度。

## 10.3 变形测试与属性测试

除固定数值外，检查物理结构上的不变量：插入明确理想的 0 dB 级不改变结果；禁用器件与从链路中移除该器件的模型结果一致；同一器件全部改名不改变数值；源输入增加 1 dB 时小信号输出增加 1 dB；在模型有效区每音增加 1 dB 时 IM3 增加 3 dB。

调整器件顺序后总增益相同不代表 NF/IP3 也相同。逐级 NF 的线性噪声贡献在本版非负附加噪声假设下应非负。压缩传递应单调，不出现增加输入后输出倒退的人工硬拐点。

## 10.4 界面验收

使用 Streamlit 官方 `AppTest` 对页面初始化、表单和结果状态做可自动化测试；复杂表格编辑、下载、视觉布局和跨软件操作用浏览器测试或人工记录补齐。[S15]

必须通过：中文标签与帮助完整、单位切换不改物理值、增删复制重排不串行、错误定位可见、修改输入后旧结果失效、重新打开项目不丢字段、页面刷新不泄漏其他会话数据。

Streamlit 自带控件的部分浏览器提示或框架文字可能需要额外审查；不能仅因业务字段中文就宣称“全部用户可见文字已完成中文化”。不建议用依赖脆弱 CSS 选择器的方式强行隐藏重要错误信息。

## 10.5 Excel 验收

| 层次 | 必须检查 |
|---|---|
| 文件结构 | 可打开，无损坏警告；中文工作表、输入、公式、快照和版本信息完整 |
| 公式有效性 | 不出现 #REF!、#DIV/0!、#VALUE!；未知状态不是通过吞掉所有异常伪装成功 |
| 实际重算 | 修改输入并在目标 Excel 重算、保存后，与 Python 按新输入重算结果一致 |
| 编辑联动 | 改 Pin、BW、温度、增益、NF、IP3、P1、启用和顺序均更新相关指标 |
| 状态联动 | 将 NF 或 P1 清空后，相关系统指标变未知，无关结果仍有效 |
| 压缩求解 | 区间检查、二分与同 p 闭式对照正常，无循环引用 |
| 快照语义 | 快照带导出时刻和输入标识，明确不随后续修改更新 |
| 预览环境 | 不支持重算的阅读器仍可查看静态快照；不把其空公式值当成数学错误 |

目标 Office 版本在需求冻结时确认；建议先验证用户实际使用的一个 Windows Excel 桌面版本，再扩大兼容矩阵。WPS、网页版 Excel 和其他阅读器不因同为 XLSX 就默认全部等价。

## 10.6 SVG、draw.io 与 VSDX 验收

SVG：结构合法、无外部资源依赖、中文完整、不同器件符号明确、图形不重叠、缩放清晰、单位和参考点正确。

draw.io：真实器件对象和分组、文字可修改、混频器有 LO 端口、节点移动后连接器仍关联、长链路可查看、重新保存打开无丢失；不得只是一个 SVG 图片对象。

VSDX：仅在声明的后端与目标 Visio 版本验收。必须打开无修复、原生形状和文本可编辑、连接器粘接、再次保存打开正常。没有该测试环境时，此格式标为未启用，不影响基础格式验收但必须如实写入交付范围。

## 10.7 安全与稳健性验收

测试名称中的 `& < > " '`、超长中文、以 `=` 开头的文本、非法文件名字符、重复 ID、无效 JSON、过高行数、路径不可写、Graphviz 超时、导出过程中修改输入、重复快速点击导出以及保存中断。

核心计算不执行用户代码；XML 不解析外部实体；不存在把用户文本拼成命令行执行的路径；错误日志不自动上传完整链路。文件临时目录和可选 Office 子进程在失败后能清理。

## 10.8 性能目标

以下是**待实测的工程目标**，不是本次已经测得的性能：在约定普通开发机上，200 级基础数值计算 p95 目标小于 100 ms；一般图形布局目标小于 5 s；200 级含压缩公式的 Excel 导出目标小于 10 s。

测试要记录 CPU、内存、系统、依赖版本、首轮／热启动区别。性能不足时先分析重复计算、布局调用和工作簿写入，不以减少必要校验或丢弃精度换取表面速度。

## 10.9 发布门槛

全部必需需求通过，核心引擎建议达到至少 90% 分支覆盖率，同时通过数值基准和状态测试。覆盖率数字本身不能替代正确性证明。

不得存在把未知参数当成默认正常值、把未验证 VSDX 当作原生可编辑文件、把静态 Excel 当作可重算工作簿、把模型估算当作实测值等严重问题。发布说明必须列出已验证环境、限制和仍未开启的可选能力。

## 11.3 开发质量要求

业务代码采用类型标注；对外函数说明单位、参考点、返回状态和异常。错误使用结构化类型，不吞掉所有异常后返回 0。共同的枚举与中文显示名称集中管理，避免 UI、Excel、JSON 各自发明不同器件名称。

## 11.4 第一轮开发最小纵向切片

第一轮可只用两级放大器完成：JSON 输入 → 校验 → 总增益/NF/IP3 → 页面结果 → 带公式的 Excel → 两个原生放大器与连接线的 draw.io → SVG。

该切片必须真的贯通；随后加入压缩与动态范围、更多器件和完整状态，而不是先做所有页面空壳。完整 V1 发布前仍须落实本计划中的全部必需模块。

## 11.5 交付与维护

正式交付时由全新环境执行安装步骤，载入示例，运行测试，生成一套导出文件。记录实际依赖版本和外部软件版本；README 写清楚需要安装什么、不安装什么仍可用、项目如何保存、Excel 如何重算、图形如何编辑。

后续升级顺序建议为：实测 AM/AM 与参数扫描 → 频率相关数据与器件库 → scikit-rf 失配分析 → 更复杂系统模型。每次升级保留旧输入迁移和旧公式版本的变更说明。

## A.1 输入模型与结果模型分离

推荐实体：

| 实体 | 必要内容 |
|---|---|
| `ProjectDraft` | UI 编辑草稿，可暂含未完成输入；不得直接传入计算内核 |
| `Project` | 通过基础格式校验的项目元数据、分析条件、有序器件、假设与来源 |
| `Stage` | ID、类型、启用、顺序、增益、噪声、IP3、P1、频率条件与器件来源 |
| `ReferencePowerSpec` | 参数状态、有限功率值、输入／输出参考定义 |
| `ValidationIssue` | 编码、级别、器件 ID、字段、中文说明、修复建议、受影响指标 |
| `Metric` | 数值／空值、单位、状态、参考点、公式／模型、依赖与假设 |
| `StageResult` | 单级输入输出、累计参数、实际估算传递、告警 |
| `ResultBundle` | 全系统与逐级结果、版本、散列、激励口径、模型有效性 |
| `DiagramScene` | 与计算顺序关联的图形节点、辅助节点、端口、连接和布局 |
| `ExportManifest` | 文件列表、格式能力、输入散列、版本、成功／失败、验证声明 |

未知有限值使用 `null` 配合 `mode="unknown"`；理想值使用 `mode="ideal"`。JSON 中的 `null` 不能独立解释成 0 或无穷。

## A.2 建议的核心接口

以下为接口契约示意，不是完整实现：

```python
def validate_and_normalize(draft: ProjectDraft) -> ValidationOutcome[Project]:
    """解析单位，检查定义域，保留缺失状态，返回规范项目或定位后的错误。"""


def calculate(project: Project) -> ResultBundle:
    """纯计算：无UI、磁盘、网络和Office依赖。每项指标独立返回状态。"""


def calculate_noise(stages: tuple[Stage, ...], conditions: AnalysisConditions) -> NoiseResult:
    """使用290 K参考NF和独立源温度，返回逐级及系统小信号噪声结果。"""


def propagate_compression(stages: tuple[Stage, ...], pin_dbm: float) -> CompressionTrace:
    """按实际估算输出传递到下一级，保留各级压缩量和模型完整度。"""


def solve_system_p1db(stages: tuple[Stage, ...], policy: SolverPolicy) -> Metric:
    """求总压缩1 dB；检查夹根、容差和模型状态，不将阈值最小值当答案。"""


def build_scene(project: Project, result: ResultBundle, options: DiagramOptions) -> DiagramScene:
    """建立不同器件图元、主链、LO和标注，确保输入散列一致。"""


def export_bundle(snapshot: ExportSnapshot, destination: Path) -> ExportManifest:
    """使用冻结快照导出，报告各格式能力；可选后端失败不能伪造文件。"""
```

函数实现前先补充实际类型定义和错误协议。不可直接复制未定义的类型名后宣称项目可以运行。

# 附录 E：公式核查与复现方法

## E.1 如何进行独立验证

正式测试不应只让程序调用自己的同一个函数两次后比较。至少采用三类证据：简单链路的手工线性量计算；实现形式不同的等价推导；具备授权与环境时的独立软件对照。

外部工具比较必须对齐频率、增益定义、参考温度、每音功率、IP3 相位假设和 P1 口径。若工具采用不同压缩模型，P1 结果不同不自动意味着某一方程序错误；应先解释模型差异，而不是为匹配数字任意调整参数。

## E.2 同 p 压缩闭式解的简要推导

将单级软饱和模型改写为线性功率形式。设输入功率为 $u$，输出为 $v$，本级线性增益为 $G$，输入 P1 对应线性功率为 $u_1$，并令 $a=10^{p/10}-1$：

$$
v=\frac{Gu}{\left[1+a(u/u_1)^p\right]^{1/p}}
$$

因此：

$$
v^{-p}=G^{-p}u^{-p}+aG^{-p}u_1^{-p}
$$

多个相同 p 的级逐层代入后，参考到链路入口的分母系数为各级 $(A_{i-1}/u_{1,i})^p$ 的和。系统压缩达到 1 dB 时，便得到第四章的闭式 P1 公式。不同 p 的级不能沿用这一简单合并式，须逐级数值传播后求根。

这也说明本文采用的“倒数求和”只在明确的模型族和参数条件下有数学依据，不能据此声称所有射频硬件都遵循同一压缩级联规律。

## E.3 最小可运行核验脚本

以下脚本仅复现部分公式基准和同 p 压缩一致性；不包含界面、文件导出、一般缺失参数处理或真实器件模型。这里只使用已知有限 P1 的测试级，避免把业务上的未知值隐式理想化。

```python
"""RF-Link-Calculator 计划文档的独立数学核验，Python 3.11+。"""
import math
import random

# 每级是 (小信号增益dB, 已知输入P1dB)，所有级使用同一个p。
Stage = tuple[float, float]


def compression_loss(x: float, ip1: float, p: float = 2.0) -> float:
    if p <= 0 or not all(math.isfinite(v) for v in (x, ip1, p)):
        raise ValueError("需要有限参数且p为正数")
    z = math.log(math.expm1(p * math.log(10) / 10))
    z += p * (x - ip1) * math.log(10) / 10
    softplus = max(z, 0.0) + math.log1p(math.exp(-abs(z)))
    return 10 / (p * math.log(10)) * softplus


def propagate(pin: float, stages: list[Stage], p: float = 2.0) -> float:
    x = pin
    for gain, ip1 in stages:
        x += gain - compression_loss(x, ip1, p)
    return x


def solve_p1(stages: list[Stage], p: float = 2.0) -> float:
    if not stages:
        raise ValueError("该核验求解器要求至少一个已知非线性级")
    prefix = 0.0
    thresholds = []
    for gain, ip1 in stages:
        thresholds.append(ip1 - prefix)
        prefix += gain
    lo, hi = min(thresholds) - 80, max(thresholds) + 20

    def residual(x: float) -> float:
        return x + prefix - propagate(x, stages, p) - 1

    if not residual(lo) < 0 < residual(hi):
        raise ValueError("初始区间没有夹住1 dB压缩点")
    for _ in range(80):
        mid = (lo + hi) / 2
        if residual(mid) > 0:
            hi = mid
        else:
            lo = mid
    return (lo + hi) / 2


def closed_p1(stages: list[Stage], p: float = 2.0) -> float:
    prefix = 0.0
    terms = []
    for gain, ip1 in stages:
        terms.append(10 ** (p * (prefix - ip1) / 10))
        prefix += gain
    return -10 / p * math.log10(sum(terms))


def main() -> None:
    f = 10 ** (3 / 10) + (10 ** (6 / 10) - 1) / 10
    nf = 10 * math.log10(f)
    iip3 = -10 * math.log10(1 / 10 + 10 / 100)
    assert abs(nf - 3.604740296956999) < 1e-12
    assert abs(iip3 - 6.9897000433601875) < 1e-12
    assert abs(compression_loss(0, 0) - 1) < 1e-12
    assert abs(solve_p1([(0, 0), (0, 0)]) + 1.505149978319905) < 1e-12
    assert abs(solve_p1([(10, 0), (10, 5)]) + 5.2069634257911215) < 1e-12

    rng = random.Random(20260923)
    errors = []
    for _ in range(100):
        stages = [(rng.uniform(-8, 25), rng.uniform(-20, 15))
                  for _ in range(rng.randint(1, 10))]
        errors.append(abs(solve_p1(stages) - closed_p1(stages)))
    assert max(errors) < 1e-9
    print(f"NF={nf:.9f} dB，IIP3={iip3:.9f} dBm")
    print(f"100条同p链路最大求解差异={max(errors):.3e} dB")


if __name__ == "__main__":
    main()
```

正式内核仍须使用带状态的领域对象，补充混合理想级、缺失值、不同 p、极端数值和搜索边界测试。不能把这段核验脚本改个文件名就当成完整应用。

## 最终实施判断

该项目适合以独立 Python 工程落地。优先把三个基础做实：**公式与参考点可靠、Excel 真正联动、图形真正按器件编辑**。在此基础上增加中文交互、数据来源和自动化验收，能够形成比零散计算表更可维护的工具。

原生 Visio、实测非线性、频率相关与复杂网络应按已验证能力逐项加入，而不是通过含糊命名或文件后缀提前宣称完成。本文为后续开发建立的是可检查的实施基线：哪些是原始要求、哪些是补充假设、采用什么算法、怎样输出、怎样证明做对，均有对应位置。
